6. The invariant a valid adaptive extension must preserve

For the family G, an ordinary pairing policy is safe: if Maker enters a still-fresh pair, Breaker takes its fresh mate; if a Breaker filler occupies a pair endpoint, that pair can be retired because every target relying on it is now Breaker-blocked. Every originally blocked target stays blocked.

At the start of each Maker turn, a sufficient invariant is:
  For every E∈G, either E∩B≠∅, or E contains a still-fresh pair from the current disjoint active matching.
Then Maker cannot complete E on its next single claim. After a non-mate reply or a pair exchange, this statement must be restored using the ACTUAL new B and actual remaining fresh cells. Saying that a released pair is “no longer needed” requires checking all live targets that depended on it, not just the exception being repaired.

The exceptions need additional adaptive protection. A legal Breaker reply cannot repair a target that Maker has just completed: check every full target immediately after each Maker claim. Multiple simultaneous one-cell threats require separate treatment. Arbitrary waiting entries and all unmatched-cell entries remain legal Maker moves; the policy must say what happens there too.

A small patch is welcome if untouched parts have a proved total response rule and all patch-boundary targets retain protection. A targetwise proof may omit exterior history only when the omitted pair is disjoint from the target and every patch domain used in its proof. “Extra Breaker stones only help” does not authorize deleting actual Maker stones or assuming a reserved patch is still pristine.
